# LocalPilot v2 Features (model picker, session deletion, adaptive completions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add to the VS Code extension (and, through the shared core + chat UI, every client): choosing chat/completion models from Ollama's installed list, deleting chat sessions, a completion-settings panel, and an adaptive completion engine that learns suggestion length and style from what the user accepts — with the outcome log designed so a later fine-tuning pipeline can consume it.

**Architecture:** Three core additions (`ollama/models`, `chat/deleteSession`/`clearSessions`, and a completion-feedback log + adaptive policy inside the engine) behind new RPC methods; chat-ui gains a model picker, a settings panel and session management (new `UiToHost`/`HostToUi` messages); the VS Code host wires them to settings and commands and reports richer completion outcomes. No model weights are trained.

**Tech Stack:** Rust (core), Preact/TypeScript (chat-ui), TypeScript (vscode). Existing test stacks.

**Spec:** `docs/superpowers/specs/2026-10-20-localpilot-design.md` §8.5 (+ §5, §7.4). Protocol source of truth: `core/src/protocol.rs`. Executors read both.

## Global Constraints

- New RPC methods and shapes (camelCase on the wire): `ollama/models {}` → `{ models: [{ name, sizeBytes, family?, supportsInsert: bool, supportsTools: bool }] }`; `chat/deleteSession { sessionId }` → `{}` (error `-32602` "turn running" if active); `chat/clearSessions {}` → `{ deleted: n }` (skips running sessions, reports them in `skipped: [...]`); `completion/outcome { requestId, outcome: "accepted"|"partial"|"rejected"|"typedThrough", acceptedText? }` (notification; `completion/accepted` and `completion/rejected` remain and map to `accepted`/`rejected`); `completion/stats {}` → `{ languages: { [lang]: { served, accepted, partial, rejected, typedThrough, acceptRate, learnedMaxLines, learnedNumPredict, examples } }, logPath, adaptive: bool }`; `completion/resetLearning {}` → `{}`.
- Outcome log: `<workspace>/.localpilot/completions.jsonl`, one JSON object per served suggestion `{ ts, requestId, lang, promptHash, contextTail (≤ 200 chars before cursor), suggestion, lines, outcome, acceptedText?, ttftMs, totalMs }`; appended on outcome (or on next served if none arrived within 60 s → `rejected`); rotated when > 10 000 lines (keep the newest 5 000). No file contents beyond `contextTail` and the suggestion.
- Adaptive policy (per language, last 50 outcomes): choose `maxLines ∈ [1, 8]` and `numPredict ∈ [16, 2 × completionMaxTokens]` maximising accepted characters per served suggestion across length buckets (1 line / 2–4 / 5–8); with < 10 outcomes use the configured values; style examples = up to 3 most recent `accepted` entries of the same language whose suggestion ≥ 2 lines, formatted into the snippet block as `# Example\n<contextTail>\n<suggestion>` (≤ 300 tokens total), refreshed only with the snippet block (never per keystroke). Setting `adaptiveCompletions` (default `true`); when `false` the engine ignores learned values and examples but still logs.
- Session deletion removes the file; the UI must drop the session and switch to the most recent remaining one (or a new one).
- Model picker lists only installed models; completion picker marks models without `supportsInsert` as "no fill-in-the-middle" (selectable but warned); selecting writes the VS Code setting (`localpilot.chatModel` / `completionModel`) → existing restart path.
- Settings panel in chat-ui edits: `completionModel`, `completionMaxTokens`, `completionDebounceMs`, `completionContextTokens`, `adaptiveCompletions`; shows `completion/stats` and a "Reset learning" button. Host persists via `workspace.getConfiguration("localpilot").update(...)` to the scope that defines the value.
- Every client host must forward the new messages; JupyterLab/JetBrains adopt them in their own packaging tasks (documented in the host contract list).
- Tests green per package; conventional commits; **no Co-Authored-By or other trailers**; push `feat/core` after each task.

## Review Focus

1. **Outcome log never leaks whole files** — only `contextTail` ≤ 200 chars and the suggestion; a test asserts the bound (Task 2).
2. **Learned values can't runaway** — bounds enforced and a language with mostly rejections falls back to the shortest bucket, never to zero tokens (Task 3).
3. **Style examples must not break KV-cache stability** — examples change only when the snippet block refreshes; a test asserts byte-identical prompts across consecutive keystrokes with examples present (Task 3).
4. **Deleting the active session mid-turn** is refused and the UI shows why; deleting another session during a turn works (Task 1 + Task 4).
5. **Model picker with Ollama down** shows the cached/last-known list or a clear "Ollama down" state, never an empty silent picker (Task 5).
