# LocalPilot Core (Rust sidecar) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `localpilot-core`, the Rust sidecar that both IDE clients talk to over JSON-RPC on stdio: Ollama client, document overlay, workspace index, inline-completion engine, agent loop with approval-gated tools, and a `bench` command that proves the latency targets.

**Architecture:** One tokio process per IDE window. A stdio JSON-RPC server dispatches client requests to three subsystems — `completion` (FIM against a small warm model), `agent` (tool-calling chat against the 27B model, with edits/commands executed by the client after approval), and `index` (gitignore-aware workspace scan + lexical search + related-snippet retrieval). All file reads go through an in-memory overlay of open documents before falling back to disk. Ollama is reached over HTTP with streaming and hard cancellation.

**Tech Stack:** Rust 1.99, tokio, reqwest (stream), serde/serde_json, ignore, notify, globset, regex, lru, similar (diffs), tokio-util (CancellationToken), tracing, clap. Dev: axum (mock Ollama), tempfile.

**Spec:** `docs/superpowers/specs/2026-10-20-localpilot-design.md` (§4–§7, §9, §10, §11, §12 step 1). Executors read both.

## Global Constraints

- Only talks to Ollama at `settings.ollamaUrl` (default `http://localhost:11434`). Never auto-starts Ollama.
- Default models: `completionModel = "qwen2.5-coder:1.5b-base"`, `chatModel = "qwen3.8:27b-mlx"`. Every Ollama request sends `keep_alive: "30m"`.
- Defaults: `completionDebounceMs = 120`, `completionMaxTokens = 64`, `chatThinking = "off"`, `completionContextTokens = 3584` (≈2 k prefix + 512 suffix + 1 k snippets), `chatContextTokens = 24000`, `completionsEnabled = true`.
- Completion prompt: prefix ≤ 2048 tokens, suffix ≤ 512 tokens, snippets ≤ 1024 tokens; multi-line completions capped at 8 lines.
- Completions return an empty list (never an error) while a chat turn is streaming.
- Edits and commands are **never** applied by the core; they go to the client via `workspace/applyEdit` / `workspace/runCommand` and the client's response is the tool result.
- All tool paths resolve inside the workspace root; `..`, absolute paths outside the root, and symlinks escaping the root are rejected.
- Index skips files > 1 MB, binaries (NUL byte in first 8 KB), and anything `.gitignore`d; multi-root is the first folder only.
- Performance targets (warm model, chat idle, measured by `bench`): TTFT p50 ≤ 250 ms / p95 ≤ 600 ms; core overhead < 5 ms p95; idle RSS ≤ 30 MB.
- Positions on the wire are `{ line, character }` with `character` in UTF-16 code units (LSP convention — both VS Code and JetBrains use UTF-16 offsets).
- Sessions persist under `<workspace>/.localpilot/sessions/`; the core creates `.localpilot/.gitignore` containing `*`.
- Commit after every task with a conventional message; `cargo fmt` and `cargo clippy -- -D warnings` clean before each commit.

## Review Focus

Inputs the spec implies but no feature test would naturally cover; each has a pinned test in the owning task.

1. **Non-ASCII text and `didChange` ranges** — a document containing emoji / CJK must map UTF-16 positions to the right bytes; an edit whose range runs past the end of the document must be clamped, not panic. (Task 4)
2. **CRLF files** — a completion at end of a CRLF line must not emit a bare `\n`, and the suffix-duplicate stop must still trigger. (Task 8)
3. **Ollama disappearing mid-session** — connection refused or HTTP 404 (model unloaded/removed) during a completion or chat turn must produce `status { ollama: "down" | "modelMissing" }` and a clean `chat/done { stopReason: "error" }`, never a crash or a hung request. (Task 5, Task 10)
4. **Malformed tool calls** — unknown tool name, missing required argument, or `edit_file` with `old == new` or `old == ""` must return a tool error to the model and continue the loop. (Task 9)
5. **Path escape attempts** — `../x`, `/etc/passwd`, and a symlink inside the workspace pointing outside must be rejected by every tool, including `create_file` for a not-yet-existing path. (Task 9)

### Task 8: Completion engine

**Files:**
- Create: `core/src/completion/mod.rs`, `prompt.rs`, `cache.rs`, `stop.rs`, `engine.rs`
- Test: unit tests + `core/tests/completion_engine.rs` (mock Ollama)

**Interfaces:**
- Consumes: Tasks 4–7, `OllamaClient`, `Settings`, Task 1 note (FIM via `suffix`, or `raw` fallback).
- Produces:
  - `prompt::build(snippets: &[Snippet], prefix: &str, suffix: &str, settings) -> FimPrompt { prompt: String, suffix: String }` where `prompt` = snippet block (each as `# Path: <path>\n<text>\n\n`, using the language's line-comment token) + `take_last(prefix, 2048)` and `suffix` = `take_first(suffix, 512)`; the snippet block is byte-identical for identical inputs.
  - `cache::CompletionCache::new(cap = 256)`; `get(uri, prefix, suffix) -> Option<String>`: exact key hit, or **typed-prefix hit**: an entry whose `prefix` is a prefix of the current prefix, same suffix, and whose completion starts with the characters typed since → returns the remainder; `put(uri, prefix, suffix, completion)`.
  - `stop::StopMode { SingleLine, MultiLine }` chosen by `mode_for(prefix, suffix)` (SingleLine if the cursor's line has non-whitespace after it); `stop::Trimmer::new(mode, suffix)`; `push(delta) -> Option<String final>` returns `Some` when a stop fires: SingleLine → at first `\n`; MultiLine → after 8 lines, or when a blank line follows a block that is now brace/paren/bracket-balanced relative to the completion start, or when the next line equals the first non-empty suffix line (duplicate); `finish() -> String` trims trailing whitespace and, for CRLF documents, emits `\r\n`.
  - `engine::CompletionEngine::new(ollama, store, index, settings)`; `request(params: CompletionRequestParams, cancel: CancellationToken) -> Result<CompletionResult, RpcError>`; `cancel(request_id)`; `set_paused(bool)` (chat gate); `on_accepted(request_id)` / `on_rejected`.
  - **Snippet cache (the heart of KV-cache reuse — not per keystroke):** the engine keeps `snippets_by_uri: HashMap<Uri, (Vec<Snippet>, Instant)>`. It is (re)computed via `related::snippets` only on `didOpen`, on `didSave` for that uri, when the watcher reports a change to that file, or when the cached entry is older than 60 s at the time of a request; the `window` passed to `related::snippets` is the 40 lines around the cursor *at refresh time*. Between refreshes, consecutive completion requests reuse the identical snippet block, so the prompt differs from the previous one only in the typed suffix of the prefix. Engine exposes `refresh_snippets(uri)` and `invalidate_snippets(uri)` for the handlers.
  - Skip rules (return empty, no model call): `!completions_enabled`; paused; document unknown; next char after cursor is `[A-Za-z0-9_]`; document > 1 MB; identical `(uri, prefix, suffix)` request already in flight (the new one joins it).
  - Model call: `num_predict = completion_max_tokens`, `temperature 0.0`, `stop = []`, streaming, chunks fed through `Trimmer`; on stop the HTTP stream is cancelled.
